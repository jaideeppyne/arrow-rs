# BYTE_STREAM_SPLIT reader reproducer

These synthetic files were generated by the standalone reproducer using ArrowWriter with eight f64 values, BYTE_STREAM_SPLIT, no dictionary, and no compression.

- valid-bss.parquet: reads back all eight original values.
- malformed-bss.parquet: the same 487-byte file, with only zero-based byte 14 changed from 16 to 126. That changes the compact-protocol page value count from 8 to 63 without moving the payload or footer.
- reproduce.rs: the exact public-API program executed in the verification run.

Unchanged upstream 32902415b841ac824470d8ee9ffd4b785d8b2a9a panics with `index out of bounds: the len is 56 but the index is 56`. Candidate b280e76f20fb9865e1657a412ceaf049e184eb88 returns its ordinary insufficient-values error.

To run inside an Arrow-rs checkout:

```sh
mkdir -p proof
cp /path/to/reproduce.rs parquet/examples/bss-review-repro.rs
cargo run -p parquet --example bss-review-repro
```

For the unpatched baseline, set BSS_EXPECT_PANIC=1 before the cargo command. The program always checks the valid file first, writes both fixtures, and asserts the expected failure mode.
